## Changes

- The wire test creates an executor with `object.__new__`, bypassing its
  constructor. Initialize the existing broker-task set and cancellation event
  in that fixture, then assert broker tasks are retired after a successful call.
- Connect's real SDK validates credentials before reaching the mock HTTP
  transport. Pass a fixed, inert test key, verify the mock request, and reject
  any call through the real synchronous or asynchronous HTTP transports. Keep
  the success, HTTP 500, cancellation, hook-removal and client-close assertions.
- A process can be reaped after `/proc/<pid>/stat` opens but before it is read.
  Treat the resulting `ProcessLookupError` as an exited process, just like a
  missing stat file. A regression opens the real stat file and then kills/reaps
  its owned child; additional checks reject false positives for live processes
  and preserve unrelated permission and I/O errors.

This first batch (`bd27bfa6`) changes only tests. Production sandbox permissions,

are unchanged by that commit.

## First Windows repair attempt (`a57fc6a7`)

The local results in this section describe that attempt. Its subsequent full
Windows CI run still failed; the remaining stream mismatch and command startup
failures are addressed in [the runner follow-up](ci-windows-runner-fixes-20261003.md).

The screenshot's long-running Windows 3.12 job subsequently finished with five
additional failures beyond those addressed above:

- Viewer startup and both offline Bench modes raised `UnicodeEncodeError` when
  printing real Chinese paths to the runner's cp1252 output stream.
- The native command test received `??` instead of Chinese text from `cmd.exe`.
- A timeout test assumed a staged Python process would print within 0.5 seconds,
  which did not hold on the runner.

Viewer and tracing diagnostics now escape only characters unsupported by the
current output stream. UTF-8 output keeps the original text, and real paths,
stream configuration and protocol output are not changed. Four regression cases
exercise the production call sites with real cp1252 and UTF-8 text streams:
the two cp1252 cases reproduced the CI failures before the fix, and all four
passed afterward. The three existing Windows subprocess acceptance cases also
passed (64.57 seconds). Seven related diagnostic/viewer/tracing cases passed on
WSL. Evidence: `ci-console-diagnostics-{red,green}-20261003.xml`,
`ci-console-acceptance-windows-20261003.xml` and
`ci-console-linux-green-20261003.xml` in `logs/`.

The Windows command runner now creates a private hidden console, selects
code page 65001, and launches a fresh command shell, because `cmd.exe` caches
its output code page at startup. Both bootstrap executables (`chcp.com` and
`cmd.exe`) use explicitly quoted System32 paths so files in the writable
snapshot cannot replace them. The code-page failure path exits immediately.
Default Python workers keep their previous no-console creation flags; LPAC
capabilities, inherited handles, atomic Job assignment and cleanup are retained.

Both command shells count against the configured Job process limit. Fewer than
two slots is now rejected explicitly; the limit is never silently increased,
and launching an external program needs another slot. The command deadline
continues to include startup time. The timeout regression emits its marker
with the shell builtin before starting Python, retaining the same 0.5-second
deadline and checking timeout, output retention and subsequent session reuse.

The command regressions cover Chinese/emoji output from builtins and Python on
both stdout and stderr, quoted paths, exit codes, an actually hidden console
with UTF-8 code page, unchanged default worker flags, snapshot bootstrap-name
collisions, process limits, isolation, cancellation and cleanup. A planted
`chcp.com` reproduced the remaining bootstrap lookup flaw before its path was
fixed; a delayed Python startup also reproduced the former timeout-marker
assumption without weakening the deadline.

The final command implementation passed **15 real Windows LPAC/Job tests** in
46.30 seconds (`logs/ci-windows-command-final-20261003.xml`), including native
process-creation failure cleanup. The command/bootstrap reproduction artifacts
are `ci-windows-command-bootstrap-red-20261003.xml` and
